# EPUB Studio Mobile v7.7.7

TXT, EPUB, 여러 권의 EPUB/TXT를 하나의 EPUB으로 정리하는 **단일 HTML 파일 웹앱**입니다.
`EPUB_Studio_Mobile_v7.7.3.html` 파일 하나를 브라우저에서 열어 사용할 수 있습니다.

> **개인정보 처리**  
> 입력 파일의 분석과 EPUB 생성은 브라우저 내부에서 수행됩니다. 앱 코드에는 파일 업로드 서버, 외부 API 호출, 추적 코드가 없습니다. 설정과 자동 저장 정보만 현재 브라우저의 `localStorage`에 저장됩니다.

---

## 1. 지원 기능

- **TXT → EPUB**: TXT 파일을 감지된 화 단위로 나누어 EPUB으로 생성
- **기존 EPUB 재편집**: 원본 리소스를 유지하면서 표지·설명·권 페이지·목차·spine 재구성
- **여러 EPUB 합본**: 여러 EPUB을 권별 독립 경로로 복사한 뒤 하나의 NAV/NCX로 합침
- **EPUB + TXT 혼합 합본**: ZIP 또는 다중 파일 선택으로 혼합 입력 처리
- **목차 자동 배정 및 수동 편집**: 제목·번호·원본 NAV/NCX를 이용한 연결과 직접 수정
- **권→화 2단계 목차**: EPUB3 `nav.xhtml`과 EPUB2 `toc.ncx`를 함께 생성
- **대표 표지·권별 표지·작품 설명 페이지 추가**
- **판권·광고·구매 안내·내부 목차·미리보기 후보 제외**
- **좌우 정렬 변경**: `text-align: justify`만 `text-align: left`로 변경
- **긴 문단 가독성 개선**: 사용자가 기능을 켠 경우에만 적용
- **생성 후 재검증**: 완성 EPUB Blob을 다시 열어 ZIP·XML·링크·CSS를 검사

지원 입력:

- `.txt`
- `.epub`
- `.zip` — 내부에 TXT, EPUB 또는 두 형식이 함께 들어 있는 경우

## 2. 권장 사용 순서

1. **1. 원본 파일 분석**에서 파일을 선택하고 `원본 분석`을 누릅니다.
2. 작품명과 작가명이 올바른지 확인합니다.
3. **4. 목차 붙여넣기**에서 다음 중 하나를 선택합니다.
   - 준비한 목차를 붙여넣고 `붙여넣은 목차로 새 권·본문 재구성`
   - `원본 목차로 자동 구성`
   - 목차 작업을 끄고 감지된 원본 후보를 하나의 `본문` 그룹으로 자동 구성
4. **4-0. 감지된 화 후보 확인**에서 표지·판권·광고·본문 후보를 확인합니다.
5. **4-1. 목차 편집**에서 권 순서, 화 순서, 제목, 원본 연결, 권 이동, 제외 여부를 수정합니다.
6. 필요하면 대표 표지, 권별 표지, 작품 설명, 정렬·가독성 옵션을 설정합니다.
7. **생성 전 검사**와 **최종 구조**를 확인합니다.
8. `EPUB 생성`을 누릅니다.
9. 생성 후 검사에 모두 통과한 경우에만 `완성 EPUB 저장` 버튼이 표시됩니다.

## 3. 목차 붙여넣기 규칙

### 3.1 권을 직접 표시하는 방식

권 구분을 적으면 입력한 구조를 우선 사용합니다.

```text
[권] 1권
1화
2화

[권] 2권
3화
4화

[권] 외전
외전 1화
외전 2화
```

다음과 같은 형식도 권 구분으로 인식합니다.

```text
[1권]
[7권 (특별 외전)]
1권
2부
외전 권
```

주의 사항:

- `외전`, `외전 1`, `특별편`만 적으면 기본적으로 **화 제목**으로 유지합니다.
- 별도 상위 권으로 만들려면 `[권] 외전` 또는 `외전 권`처럼 적습니다.
- 게임·채팅 소설의 대괄호 대사 줄은 단순히 대괄호가 있다는 이유만으로 권으로 처리하지 않습니다.

### 3.2 권 표시 없이 화만 적는 방식

```text
1. 제안
2. 복귀
3. 선택
```

각 제목을 전체 원본에서 검색한 뒤 실제 본문이 들어 있는 원본 파일 아래로 배정합니다.

### 3.3 화 번호 범위 방식

```text
1권: 1화 ~ 28화
2권: 29화 ~ 56화
```

또는 다음처럼 입력할 수 있습니다.

```text
[1부]
1.~7.

[2부]
1.~10.
```

지원 범위 구분자:

- `~`
- `-`
- `–`
- `—`

범위는 번호별 항목으로 펼친 뒤 원본 후보에 연결합니다. 번호가 권마다 다시 시작되는 작품은 요청된 출현 횟수만큼 순서대로 사용합니다.

### 3.4 제목 매칭

- 마침표, 공백, 일부 번호 표기 차이는 정규화합니다.
- 화 번호가 명확하면 번호 일치를 우선합니다.
- 제목 유사도 매칭을 사용하지만 짧은 대사형 제목은 오배정을 줄이기 위해 더 엄격하게 처리합니다.
- 자동 연결이 맞지 않으면 **4-1 목차 편집**에서 `연결할 원본 본문`을 직접 선택합니다.

## 4. TXT 화 인식

기본값은 `자동 감지`입니다.

대표적으로 다음 형식을 인식합니다.

```text
#1
1화
제1화
Chapter 1
EP01
Prologue
Epilogue
외전 1화
```

TXT 안에 내부 목차가 있는 경우, 목차에 나온 제목이 본문에서 다시 등장하는 위치를 실제 화 시작점으로 찾습니다.

오인식된 `#2948` 같은 항목은 **4-0. 감지된 화 후보 확인**에서 체크를 해제할 수 있습니다. 체크를 해제한 시작점은 새 화로 사용하지 않으며, 해당 원문은 앞선 유효 화 본문에 남을 수 있습니다.

직접 정규식을 사용할 때는 `직접 입력한 정규식`을 선택하고 JavaScript 정규식 패턴을 입력합니다.

## 5. 여러 EPUB 합본 처리

여러 EPUB을 합칠 때 각 원본은 별도의 하위 폴더로 복사됩니다. 동일한 파일명이 있어도 원본별 경로가 분리되므로 충돌을 줄입니다.

처리 원칙:

- 원본 EPUB의 CSS, 이미지, SVG, JavaScript 및 기타 실제 리소스를 복사
- 원본에 manifest 등록이 빠진 리소스도 파일이 실제로 존재하면 복사 후 합본 OPF에 등록
- 원본 NAV/NCX는 합본에 그대로 중복 등록하지 않음
- 합본용 `nav.xhtml`과 `toc.ncx`를 각각 하나만 생성
- 원본 표지 이미지는 리소스 보존용으로 남길 수 있지만 `cover-image` 속성은 합본 대표 표지 하나에만 부여
- 표지·판권·내부 목차 등으로 판정된 XHTML은 기본 본문 후보에서 제외
- 자동 판정이 틀렸으면 4-0 화면에서 직접 포함 또는 제외

## 6. 표지와 작품 설명

### 대표 표지

새 대표 표지를 선택하면 다음 항목을 구성합니다.

- 표지 XHTML
- EPUB3 `cover-image` 속성
- EPUB2 `<meta name="cover">`
- OPF guide의 cover 참조
- spine 첫 항목

새 대표 표지를 선택하지 않으면 원본 표지 정보를 우선 탐색합니다.

### 권별 표지

각 권에서 다음 중 하나를 선택할 수 있습니다.

- 원본 표지 사용
- 새 이미지 선택
- 표지 없음

표지가 없더라도 권 제목만 중앙에 표시하는 별도 권 XHTML을 만듭니다.

### 프로젝트 JSON과 이미지

브라우저의 보안 제한 때문에 프로젝트 JSON에는 이미지 파일 자체를 넣지 않습니다.

다음 이미지는 프로젝트를 다시 불러온 뒤 재선택해야 합니다.

- 대표 표지
- 작품 설명 이미지
- 새로 선택한 권별 표지

실행 취소·다시 실행 중에는 현재 브라우저 세션의 `File` 객체를 유지하도록 처리되어 있습니다.

## 7. CSS 보존과 선택적 변경

기본 원칙은 원본 CSS 보존입니다.

`원본 CSS 파일 목록·개수 확인`이 켜져 있으면 다음을 비교합니다.

- 예상 출력 경로에 CSS 파일이 존재하는지
- 각 원본 CSS의 내용 SHA-256 해시가 예상값과 같은지
- 다권 합본에서는 각 원본과 복사된 출력 경로의 대응

### 좌우 정렬 변경

`좌우 정렬을 왼쪽 정렬로 변경`을 켠 경우에만 다음 선언을 바꿉니다.

```css
text-align: justify;
```

```css
text-align: left;
```

`text-align-last: justify`와 XHTML의 `align="justify"`, 인라인 style도 같은 원칙으로 처리합니다. `!important`가 있으면 유지합니다.

이 옵션을 사용한 경우 CSS 검사는 원본 해시가 아니라 **해당 치환을 적용했을 때 예상되는 해시**와 비교합니다. 다른 선언이 달라지면 검증에서 실패합니다.

### 긴 문단 가독성 개선

이 기능은 기본적으로 꺼져 있습니다. 켠 경우에만 지정한 최소 길이와 문장 수를 기준으로 문단을 분리합니다.

안전 모드에서는 기본적으로 다음 문단을 제외합니다.

- class 또는 id가 있는 문단
- 내부 태그가 있는 문단
- 이미지·SVG·스크립트가 포함된 문단

처리에 실패한 XHTML은 건너뛰고 파일명과 오류를 생성 로그에 표시합니다.

## 8. 생성 후 실제 검증

EPUB을 생성한 뒤 메모리상의 작업 ZIP만 검사하지 않습니다. 최종 Blob을 다시 열어 다음 검사를 수행합니다.

### ZIP 검사

- ZIP CRC32 재검사
- ZIP 첫 로컬 항목이 `mimetype`인지 확인
- `mimetype` 압축 방식이 STORE인지 확인
- `mimetype` 내용이 `application/epub+zip`인지 확인
- 필요하면 `mimetype`을 첫 항목으로 두어 재패키징

### XML·패키지 검사

- `META-INF/container.xml` 파싱
- container의 OPF 경로 확인
- OPF 파싱
- EPUB3 NAV 파싱
- EPUB2 NCX 파싱
- manifest의 모든 파일 존재 확인
- manifest ID와 href 중복 확인
- spine의 모든 `idref` 확인
- NAV가 spine에 포함되지 않았는지 확인

### 목차 검사

- NAV에 `nav epub:type="toc"`가 있는지 확인
- NAV의 모든 링크 대상 및 fragment ID 확인
- NCX `dtb:depth`가 2인지 확인
- NCX `playOrder`가 1부터 연속이며 중복이 없는지 확인
- NCX의 모든 링크 대상 및 fragment ID 확인
- NAV와 NCX 항목 수가 같은지 확인
- 권 링크와 해당 권 첫 화 링크가 서로 다른지 확인

### XHTML·CSS 리소스 링크 검사

- XHTML/SVG의 `href`, `src`, `poster`, `data`, `xlink:href`
- `srcset` 대상
- CSS의 `url(...)`
- CSS의 `@import`
- OPF guide 참조

외부 URL, `data:`, `mailto:` 같은 스킴은 EPUB 내부 파일 검사 대상에서 제외합니다.

검사 실패 시 다운로드 버튼을 표시하지 않고 오류 원인을 생성 로그와 오류 창에 표시합니다.

## 9. 프로젝트 저장과 자동 저장

- 편집 상태는 약 1.2초 지연 후 자동 저장됩니다.
- 연속 입력 시 앞선 타이머를 취소하고 마지막 상태만 저장합니다.
- 페이지를 닫기 전에는 즉시 저장을 한 번 시도합니다.
- 저장 공간 부족이나 브라우저 저장 제한이 발생하면 로그에 경고합니다.
- 프로젝트 JSON은 제목, 설명, 목차, 그룹, 화 연결, 후보 선택 및 옵션을 저장합니다.
- 이미지 파일 자체와 원본 도서 파일 자체는 프로젝트 JSON에 포함하지 않습니다.

브라우저 데이터나 사이트 저장 공간을 지우면 자동 저장본과 설정도 삭제됩니다.

## 10. 문제 해결

### 파일을 읽지 못했습니다

클라우드 전용 상태의 파일은 기기에 먼저 내려받은 뒤 선택합니다. 손상된 ZIP/EPUB은 브라우저에서 열리지 않을 수 있습니다.

### 생성 버튼이 비활성화됩니다

- 원본 분석이 끝났는지 확인합니다.
- 목차 작업을 켠 상태라면 목차 구성 또는 원본 목차 자동 구성을 먼저 실행합니다.
- 목차 작업을 끄면 감지된 원본 후보가 있을 때 `본문` 그룹을 자동으로 만듭니다.

### 특정 화가 연결되지 않습니다

4-1 화면에서 해당 화의 `연결할 원본 본문`을 직접 선택합니다. 엄격 검증이 켜져 있으면 미배정·미사용·중복·불일치가 남아 있을 때 생성을 차단합니다.

### 표지나 설명 이미지가 프로젝트 불러오기 후 사라졌습니다

프로젝트 JSON에는 이미지 파일이 저장되지 않습니다. 원본 파일과 이미지를 다시 선택합니다.

### 큰 파일에서 브라우저가 느려집니다

모든 처리를 브라우저 메모리에서 수행하므로 입력 파일이 매우 크거나 EPUB 수가 많으면 메모리 사용량이 증가합니다. 다른 탭을 줄이고 데스크톱 Chrome 또는 Edge 계열 최신 브라우저에서 처리하는 편이 안정적입니다.

## 11. v7.7.3 변경 사항

- 목차 재구성을 끈 상태에서 기본 `본문` 그룹을 **생성 전 검증보다 먼저** 만들도록 수정
- 목차 재구성을 끄면 생성 버튼을 사용할 수 있도록 UI 상태 수정
- 자동 저장 타이머 중복 예약 수정 및 종료 전 즉시 저장 추가
- 설정 저장·불러오기·삭제의 저장소 예외 처리 보강
- 실행 취소·다시 실행 기록에 현재 세션의 권별 표지 `File` 객체 유지
- 편집 화면 렌더링 시 변경 상태를 자동 기록하여 제목·순서·연결 변경의 undo/redo 보강
- 프로젝트 JSON에 이미지가 포함되지 않는다는 경고 추가
- 완성 EPUB Blob 재개방 및 CRC32 검사 추가
- `mimetype` 첫 항목·STORE·내용 검사 및 필요 시 재패키징 추가
- OPF, NAV, NCX, XHTML, SVG XML 재파싱 추가
- manifest, spine, NAV, NCX, guide, XHTML, SVG, CSS 내부 링크 검사 추가
- fragment ID 존재 검사 추가
- NAV/NCX 항목 수, NCX depth/playOrder, 권 링크와 첫 화 링크 분리 검사 추가
- 원본 CSS 경로 및 SHA-256 내용 대조 추가
- Web Crypto를 사용할 수 없는 환경을 위한 순수 JavaScript SHA-256 대체 구현 추가
- 좌우 정렬 처리를 `justify` 선언 삭제가 아니라 `left` 치환으로 통일
- 인라인 `align="justify"`와 style 치환 정규식 수정
- 가독성 개선 실패 파일을 숨기지 않고 로그에 표시
- 반복 생성 시 이전 EPUB Blob URL 해제
- 단일 EPUB의 원본 표지 탐색을 cover 후보·guide·이름 순으로 보강
- 다권 합본에서 원본 NAV/NCX는 제외하고 실제 리소스를 독립 경로에 보존
- 원본 표지 이미지는 리소스로 보존하되 합본 대표 표지만 `cover-image`로 등록
