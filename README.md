# EPUB Studio Mobile v8.2.3 — 목차 인식 종합판

## v8.2.3 변경 (이번 판)

- **번호 있는 외전(`외전 2 - 어떤 날`) 미인식, 부(部) 표시(`01.`/`02.`) 오인식, 대사 줄이 가짜 화로 잡히던 문제 수정 (예: '해후').** 세 가지를 고쳤습니다.
  1. `외전 - 제목`뿐 아니라 `외전 2 - 제목`처럼 번호가 붙은 외전도 자동 인식합니다.
  2. `10. 틈` 바로 뒤의 `01.`·`02.`처럼, 앞 화보다 번호가 작고 본문이 없는 맨숫자는 화가 아니라 부(部) 표시로 보고 목차에서 제외합니다.
  3. 붙여넣은 목차로 배정할 때, 본문의 대사(`"좋은 사람?"`)가 목차 제목(`7. 좋은 사람`)과 느슨히 일치해 가짜 화로 끼어들던 것을 막았습니다(따옴표로 감싼 대사 줄은 화 제목에서 제외).



## v8.2.2 변경

- **리디 붙여넣기: 작품 소개 끝에 '작가/링크/트위터/블로그'가 딸려 들어가던 문제 수정 (예: '안녕과 안녕').** 일부(주로 예전) 리디 페이지는 작가 섹션 제목이 '작가 프로필'이 아니라 그냥 '작가'라서 소개 끝 경계를 못 찾고 작가·링크 줄까지 소개에 포함됐습니다. 이제 '작가 프로필'과 '작가'(및 링크/리뷰/키워드) 모두를 경계로 인식해, 작품 소개 본문만 깔끔하게 채웁니다.



## v8.2.1 변경

- **리디 붙여넣기: '작품 소개'와 '목차'를 자동 구분해서 각각 채우도록 수정.** 리디는 '작품 소개'와 '목차'가 서로 다른 탭이라, 복사할 때 그 순간 보이던 탭 내용만 딸려옵니다. 이제 붙여넣은 '작품 정보' 아래 내용이 **산문이면 작품 소개 칸**에, **권·화 목록이면 목차 칸**에 자동으로 들어갑니다. (작품 소개의 '미리보기' 샘플 본문은 제외.) 소개 탭과 목차 탭을 각각 한 번씩 붙여넣으면 두 칸이 모두 채워집니다(서로 덮어쓰지 않음).



## v8.2 변경

- **리디 페이지 붙여넣기 → 제목·작가·작품소개·BL가이드·목차 자동 채우기 (새 기능).** 1번 탭에 '📋 리디 페이지 붙여넣기' 칸이 생겼습니다. 리디북스 작품 페이지를 전체 선택→복사해서 붙여넣고 버튼을 누르면, 여러 칸을 한 번에 자동으로 채웁니다. 작품마다 소개·가이드·목차를 따로따로 복붙하던 것을 붙여넣기 한 번으로 줄여, 여러 작품을 만들 때 시간을 크게 아낍니다.
  - 자동 채움: 제목 / 작가 / 작품 소개(페이지에 있으면) / BL 가이드 / 목차(권·외전 구조 포함).
  - 표지·소개 이미지는 리디가 외부 접근을 차단해 자동으로 못 가져옵니다 → 직접 업로드하세요.
  - 리디 페이지 구조에 따라 한두 칸은 손봐야 할 수 있습니다(대부분 그대로 사용 가능).



## v8.1.6 변경

- **플레인 '외전'·'AU 외전' 같은 권 구분과, 번호 겹치는 외전 화가 미배정되던 문제 수정 (예: '소 잃고 가이드 고치기').** 두 가지를 고쳤습니다.
  1. `[1권]`처럼 괄호 없이 빈 줄로 나눈 목차에서 `외전`·`AU 외전`·`특별 외전` 블록도 **권 구분으로 인식**합니다(1권~N권 같은 권 구분이 함께 있는 목차에서만 적용, 평범한 목차엔 영향 없음).

## v8.1.5 변경

- **내부 목차 뒤에 오는 '프롤로그'(서장·서막 등)가 미배정되던 문제 수정 (예: '평화 강탈').** 파일 안에 '목차' 목록이 있고 그 목록엔 프롤로그가 빠져 있는데 본문은 프롤로그로 시작하는 경우, 내부 목차 제외 범위가 프롤로그까지 삼켜서 프롤로그가 매칭되지 않았습니다. 이제 목차 목록 다음에 나오는 프롤로그·서장류 머리말을 **본문의 시작으로 인식**해, 붙여넣은 목차의 프롤로그가 제대로 배정됩니다. (본문이 대사 "…"로 시작하는 경우 포함. 목차 목록 안에 프롤로그가 있는 경우는 종전대로 처리.)



## v8.1.4 변경

- **'제목만 있는 페이지'와 '본문 페이지'가 따로 나뉜 EPUB에서 한 화가 목차에 두 번 나오던 문제 해결 (예: '그라티아' 같은 칼리브레 분할본).** 제목(`극야 上`)과 본문이 서로 다른 파일이라 목차에 '극야 上'과 본문 첫 문장이 각각 떠서 항목이 두 배로 보였습니다. 이제 **제목 전용 페이지를 바로 다음 본문 화에 합쳐** 하나의 화로 만듭니다(제목은 본문 맨 위 제목으로 들어감). 그 결과 목차가 원본 의도대로(예: 도르센의 대공 · 극야 上 · 극야 下 …) 깔끔하게 나옵니다. (본문이 있는 일반 EPUB 화에는 영향 없음.)



## v8.1.3 변경

- **칼리브레 분할 EPUB의 '제목만 있는 페이지' 제목이 깨져 읽히던 문제 수정.** 제목이 `<b><p style="text-align:center">&lt;2&gt; 극야 上</p></b>`처럼 들어있고 `&nbsp;`가 섞여 XML 파싱이 실패하던 페이지에서, 제목이 `&nbsp; &nbsp; &lt;2&gt; …`처럼 깨져 잡혔습니다. 이제 **HTML 엔티티를 해석하고 앞의 장 번호 표식(`<2>`, `＜2＞`, `[2]` 등)을 떼어** 제목을 `극야 上`처럼 깔끔하게 읽습니다.



## v8.1.2 변경

## v8.1.1 변경

## v8.0.9 변경

- **`[특별 외전]` 등 '외전' 계열 대괄호 권 헤더 인식 확대.** `[특별편]`뿐 아니라 `[특별 외전]`·`[외전]`·`[외전 1]`·`[번외편]`·`[후일담]`도 권(그룹) 헤더로 인식합니다.

## v8.0.8 변경

- **`제목(N)~(M)` 형식의 물결/작대기 범위 표기 자동 전개.** 예전에는 `1~13`, `1화~30화` 같은 숫자 범위만 펼쳤는데, 이제 **`확장(1)~(3)` → 확장(1)·확장(2)·확장(3)**, `전개(1)~(2)`, `반격(1)~(2)`처럼 **제목 + 괄호 파트 번호 범위**도 자동으로 개별 화로 펼칩니다. (`외전(1), Lover`처럼 범위(~)가 없는 항목이나 `2-1.` 같은 부번호는 그대로 둡니다.)



## v8.0.7 변경

- **`<pre>`/pre-wrap 본문 문단 변환 시: 원본이 지정한 글꼴·글자크기를 무시하고 리더(사용자) 설정을 따르도록 변경.** v8.0.6까지는 원본 글꼴·크기를 유지했는데, 요청에 따라 이제 **글꼴·크기를 아예 지정하지 않아** 리더 앱에서 사용자가 정한 글꼴·크기가 그대로 적용됩니다. (원본 인라인 스타일의 글꼴·크기 선언은 제거하고, 컨테이너 선택자의 글꼴은 변환으로 자연히 무력화됩니다.) 줄간격·문단 간격·정렬·제목 스타일은 종전대로 통일된 기본값을 씁니다.



## v8.0.6 변경

- **`<pre>`/pre-wrap 본문 문단 변환 시: 글자체·글자크기만 원본 유지, 나머지는 일관된 기본값으로 통일.** v8.0.5에서 원본 CSS 값을 다 가져오다 보니 파일마다 줄간격·들여쓰기가 제각각이 됐습니다. 이제 **`font-family`·`font-size`는 원본 그대로 두고**(글꼴·크기 보존), **줄간격(1.8)·문단 간격·들여쓰기·정렬·제목 스타일은 앱 고정 기본값**으로 통일해 어떤 파일을 합쳐도 일관되게 보이도록 했습니다.



## v8.0.5 변경

- **`<pre>`/pre-wrap 통짜 본문을 문단으로 변환할 때 원본 글꼴·글자크기·줄간격을 그대로 유지.** 이전에는 변환하면서 컨테이너(예: `pre.body`, `.text`)에 지정된 `font-family`·`font-size`·`line-height`가 사라지고, 앱이 넣은 값(줄간격 1.8, 큰 가운데 제목 등)으로 덮여 원본과 달라 보였습니다. 이제 변환 시 **그 xhtml이 참조하는 CSS(외부·인라인)에서 원본 컨테이너의 글꼴·크기·줄간격·들여쓰기를 추출해 그대로 적용**합니다. (예: 피아니스트는 `font-family:serif; font-size:1em; line-height:1.9`, 솔베이지는 `line-height:1.8`가 그대로 유지됨.) 제목도 원본 크기를 상속하도록 바꿔 과하게 커지지 않습니다.

## v8.0.3 변경

- **'붙여넣은 목차로 재구성' 버튼에 처리 중 표시 추가.** 목차가 많으면 버튼을 눌러도 반영까지 잠깐 멈춘 것처럼 보였습니다. 이제 누르면 버튼이 **`… . . .`**(점 표시)로 바뀌고 은은하게 깜빡이며 비활성화됐다가, 반영이 끝나면 원래 상태로 돌아옵니다. 처리 중 중복 클릭도 막습니다. (오류가 나도 버튼은 정상 복구됩니다.)



## v8.0.2 변경

- **왼쪽 정렬이 적용 안 되던 문제 수정.** `text-align: justify`가 CSS 주석(`/* ... */`) 바로 뒤에 오면 치환 정규식이 못 잡아 그대로 남았습니다(리디북스 최적화 CSS에서 흔함). 이제 주석·`}` 뒤에 오는 `justify`(및 `!important`)도 `left`로 바꿉니다.

## 지원하는 목차 형식

### 권(볼륨) 구분
- `[1권]` 대괄호형
- `<2권>` 꺾쇠형 (그리고 `【3권】`·`《외전 권》` 등 전각 괄호)
- `제4권`, `1권`
- `5권 (외전)`, `6권 (외전2)` → **권으로 인식**
- (별도 외전권은 `외전 권` 또는 `[권] 외전`)

### 화(챕터)
- 번호만: `1`, `2`, `01`
- 한글/임의 제목: `어느날`, `그날 밤`
- `1화`, `제3화`, `1장`, `제2장` 등
- **날짜형 제목**: `1992년 6월 14일 일요일`처럼 날짜가 곧 화 제목인 일기/연재 형식
  - 서로 다른 날짜(요일까지 달라도)를 유사도로 잘못 합치지 않습니다
  - **에필로그의 중복 날짜**(예: 1권 첫 화와 같은 `1992년 6월 14일`)도 각각 제 위치에 정확히 배정

### EPUB 내부 화 자동 감지
- heading(h1~h6)이 없고 `<p><b>01.</b></p>`처럼 **굵은 숫자 문단**으로만 화가 구분된 EPUB(Calibre 변환본 등)도 자동으로 화를 나눕니다.
- 한 권이 여러 파일(index_split_000/001/002 …)로 나뉘어 있어도, 그 안의 굵은 숫자 화를 모두 찾아 쪼갭니다.
- **오탐 방지**: 본문 속에 우연히 들어간 숫자(예: 삐삐 화면 `0 1 2 4.`, `6.25` 같은 표기)는 화로 잡지 않습니다. `<b>`/`<strong>`로 강조됐거나 heading 태그인 순수 번호가 2개 이상일 때만 화로 인식합니다.
- 목차 없이 자동으로 잡히지만, 원하면 `1권` 아래 `1 ~ 13`처럼 범위를 붙여넣어 명시할 수도 있습니다.

### 상위 구분(문맥) — 그 아래 화 번호가 재시작돼도 OK
- `chapter 1`, `Chapter 1` (대소문자 무관)
- `Chapter One`, `Chapter Two` … (영어 숫자 단어)
- `[chapter 1]` (괄호로 감싼 형태)
- `part 1`, `파트 1`
- `제1장 / 1장`, `제1부 / 1부`
- **각 구분 아래에서 `1·2·3`처럼 번호가 다시 시작해도** 문맥별로 서로 다른 본문에 정확히 배정
- **구분 제목 자체에 본문이 있어도, 없어도, 섞여 있어도** 모두 처리
  - `장 / 부`는 그 아래 번호가 재시작되면 상위 문맥으로, 아니면 그냥 회차로 **자동 판단**

> 오탐 방지: `1장면 전환`·`1부분만`·`장난감`·`부산 여행`처럼 우연히 장/부가 들어간 일반 제목은 문맥으로 잡지 않습니다.

## 무엇이 문제였고 어떻게 고쳤나 (요약)

1. **꺾쇠·전각 괄호 권(`<2권>` 등)을 못 잡던 문제** — 권 헤더/마커 판정을 대괄호·꺾쇠·전각 괄호 모두 인식하도록 확장하고 괄호를 벗겨 정규화.
2. **chapter 번호 재시작에서 뒤 화가 비던 문제(가장 심각)** — 본문 시작을 "제목 반복 + **바로 다음 실제 줄이 산문**"일 때로 판정(`nextNonBlankIsProse`). 구분선(`* * *`)·워터마크(`@…`)는 건너뜀. 내부 목차 범위 탐지와 자동 추출 양쪽에 적용.
3. **순수 번호(`1`, `01`) 헤딩이 매칭 안 되던 문제** — 숫자만으로 된 한 줄을 헤딩 번호로 인정.
4. **본문 없는 chapter가 생성을 막던 문제** — chapter/part 같은 구조 제목은 미배정이어도 차단 대상에서 제외.
5. **chapter 표기 확장** — `Chapter One`(영어 숫자단어)·`[chapter 1]`(괄호형)·`제1장/1장`·`제1부/1부`를 문맥으로 인식. 영어 숫자단어는 번호로 환산해 `Chapter One`/`Chapter Two` 라벨이 뒤섞이지 않게 처리.
6. **날짜형 목차가 서로 섞이던 문제** — `1992년 6월 14일`처럼 날짜가 제목이면, 기존 매칭이 맨 앞 숫자(연도 1992)만 보고 유사도로 이웃 날짜까지 끌어와 권 배정이 뒤엉켰습니다. → **양쪽 다 숫자를 포함하고 숫자열(선행 0 무시)이 다르면 유사도와 무관하게 다른 화**로 판정. 요일이 달라 어간 비교를 우회하는 경우까지 차단. 중복 날짜(에필로그 등)도 권 구간·순서로 정확히 배정.
7. **EPUB '굵은 숫자' 화 자동 감지** — heading 없이 `<p><b>01.</b></p>`로만 화가 구분된 EPUB도 자동 분할. 권이 여러 파일로 나뉘어 있어도 그 안의 번호 화를 모두 찾음(순수 번호 화 2개 이상 + 굵게/heading 조건). 본문 속 숫자(삐삐 화면 등)는 오탐 제외.
8. **(이전 판 유지) "차례" 내부 목차 인식** — 헤더가 `목차`·`차례`·`목 차`·`contents`여도 인식, 워터마크·산문 오인 방지, 1화짜리 권 정상 분리.

> 목차 파서/매칭 엔진의 핵심 알고리즘은 유지했습니다. **인식 범위(헤더·항목·권 괄호·chapter 표기)와 헤딩-번호 인식, 본문 시작 판정**만 정교화했습니다.

## 사용 팁

- **합본(한 TXT에 여러 권)**: 파일 안에 `<2권>`·`[3권]`·`제4권`·`5권 (외전)` 같은 줄이 있으면 자동으로 권을 나눕니다.
- **붙여넣는 목차**: 권 헤더는 `[1권]`·`<2권>`·`5권 (외전)`처럼, 하위 화는 그 아래 `1`/`어느날`/`1화`처럼. 상위 구분은 `chapter 1`·`제1장`·`제1부` 등으로 두고 번호를 재시작해도 됩니다.
- **chapter 재시작이 있는 파일**은 목차를 붙여넣는 방식이 가장 정확합니다(문맥 구분이 확실해짐).
- `장`/`부`가 실제로는 회차인지 상위 구분인지는 그 아래 번호 재시작 여부로 자동 판단하지만, 애매하면 목차를 붙여넣어 명확히 해주세요.
- 특이 형식으로 목차가 안 잡히는 파일이 있으면 그 파일의 **목차 헤더 표기와 제목 몇 줄**을 알려주시면 바로 반영하겠습니다.

## 자주 하는 실수 (중요)

- **목차와 본문의 형식은 같아야 합니다.** EPUB 본문의 화 제목이 숫자(`01. 02.`)인데 목차 칸에 날짜(`1992년 6월 14일`)를 붙여넣으면 서로 매칭되지 않아 "미배정·본문 없음"이 대량 발생합니다.
- **홈페이지(연재 사이트) 목차**를 그대로 붙여넣을 때는, 그 목차의 화 개수·순서가 EPUB 실제 화와 정확히 같은지 먼저 확인하세요. 사이트에서 회차를 합치거나 빠뜨린 경우 개수가 어긋나 뒤로 갈수록 다 밀립니다.
- 숫자로만 구분된 EPUB은 **목차 칸을 비우고 자동**으로 두는 것이 가장 확실합니다. 굳이 넣으려면 `1권` 아래 `1 ~ 13`처럼 숫자/범위로 넣으세요(날짜 X).
