# EPUB Studio Mobile v7.9.50 — `<pre>` 본문·EPUB 권 메타데이터 보정판

이번 판은 실제 ZIP과 사용자가 붙여넣은 아래 목차를 그대로 기준으로 실패를 재현한 뒤 수정했습니다.

```text

02. 영혼의 이면
03. 추격

```

### 실제 원인 1 — ZIP 내부 EPUB 파일명의 권 번호가 실제 내용과 반대

- 파일명 `... 1권.epub`의 OPF `dc:title`은 실제로 **관 속의 피아니스트 2권**이고 본문도 `06. 거울`부터 `외전. 네 손을 위한 환상곡`까지 들어 있습니다.
- 파일명 `... 2권.epub`의 OPF `dc:title`은 실제로 **관 속의 피아니스트 1권**이고 본문도 `01. 장송 행진곡`부터 `05. 밤의 가스파르`까지 들어 있습니다.
- 이전 판은 다권 EPUB의 권 번호를 파일명에서만 가져와 `[1권]` 목차를 실제 2권 본문에 대입했습니다.
- 이제 OPF `dc:title`에 명시적인 `N권`/부록 권 정보가 있으면 **EPUB 내부 메타데이터의 권 정보를 파일명보다 우선**합니다.

### 실제 원인 2 — 화 제목이 `<pre>` 안의 일반 텍스트 줄

이 파일은 `body.xhtml` 하나 안에 본문 전체가 다음처럼 들어 있습니다.

```xhtml
<pre class="body">
01. 장송 행진곡
...본문...
02. 영혼의 이면
...본문...
</pre>
```

이전 내부 제목 탐색은 `h1~h6`, `p`, `div`, `section`만 검사해 `<pre>` 내부의 `01. ...` 같은 줄은 전혀 찾지 못했습니다. 그래서 각 권을 `본문` 한 덩어리로만 인식했습니다.

수정 사항:

- **붙여넣은 목차가 있을 때 `<pre>` 내부의 각 텍스트 줄도 요청 제목과 직접 대조**합니다.
- 일치한 줄은 각각 별도 `epub-fragment` 후보로 만들어 NAV/NCX에서 독립 회차처럼 사용할 수 있습니다.
- 최종 EPUB 생성 시 `<pre>`의 텍스트와 공백은 그대로 두고 각 제목 줄 바로 앞에 빈 `<span id="...">` 앵커만 삽입합니다. 따라서 원본 `<pre>` 표시 형식을 유지하면서 목차 클릭 위치를 분리합니다.
- 현재 권 안에서 제목을 못 찾을 경우, 파일명/메타데이터가 잘못된 EPUB을 대비해 **전체 미사용 후보에서도 강한 제목 일치를 한 번 더 찾은 뒤** 순서 폴백을 사용합니다.

# EPUB Studio Mobile v7.9.48 — 목차 인식 경로 통합·회귀 수정판

## v7.9.48 변경 (전체 경로 재검토)

- **핵심 원인 1 — v7.9.47 수정이 모든 붙여넣기 경로에 들어가지 않았음.** v7.9.47의 “헤더 없는 앞쪽 목차 제거”는 `[권] 1권`처럼 상위 권이 명시된 TXT 재구성 경로에는 적용됐지만, `1화 / 2화 / 3화`처럼 **권 없이 평평하게 붙여넣는 TXT 경로에는 빠져 있었습니다.** 이 경로는 같은 제목이 두 번 나오면 첫 등장을 남겼기 때문에, 앞쪽 내부 목차가 먼저 잡히고 뒤의 실제 본문 제목이 버려질 수 있었습니다. → 자동 감지·권 있는 붙여넣기·권 없는 붙여넣기가 모두 `stripLeadingHeaderlessTocMarkers()` 하나를 사용하도록 통합했습니다.
- **핵심 원인 2 — 앞쪽 목차 제거가 마지막 목차 항목을 남길 수 있었음.** 기존 방식은 “현재 마커와 다음 마커 사이가 거의 비었는지”를 한 줄씩 검사했습니다. 마지막 목차 항목과 실제 본문 첫 화 사이에 장식문구·안내문이 있으면 그 마지막 목차 항목만 남고, 이후 중복 제거에서 실제 첫 화가 삭제될 수 있었습니다. → 앞쪽 **목록 전체가 뒤에서 반복되는지 + 앞 목록 자체가 조밀한지**를 함께 판단한 뒤 실제 본문 시작점 앞을 통째로 제거하도록 변경했습니다.
- **다권 EPUB의 순번 강제 매칭 제거.** 원본 권 수와 붙여넣은 권 수가 같으면 예전에는 각 권의 `0번째→0번째, 1번째→1번째` 후보를 제목 확인 없이 연결하고, 남은 원본 후보까지 목차 뒤에 자동 삽입했습니다. 앞에 부가 페이지가 하나만 끼어도 이후 화가 전부 밀릴 수 있었습니다. → 각 권 안에서 **제목/번호 강한 일치 우선 → 정보가 부족할 때만 순서 폴백**으로 바꾸고, 사용자가 붙여넣지 않은 남은 후보는 자동 삽입하지 않습니다. 남은 실제 본문은 검증 단계의 `미사용 본문`으로 표시합니다.
- **불완전한 NAV/NCX 때문에 본문이 사라지는 문제 완화.** 원본 목차에 없는 XHTML이라는 이유 하나만으로 후보에서 제외하지 않습니다. 판권·광고 등 별도 부가페이지 판정까지 동시에 맞을 때만 자동 제외하고, 본문 가능성이 있으면 후보로 보존합니다.
- **`1장/2장/3장` 문맥 판정 수정.** README에는 장/부가 하위 번호 재시작 여부에 따라 상위 문맥인지 일반 회차인지 자동 판단한다고 되어 있었지만, 실제 `parseToc()`는 모든 `N장/N부`를 무조건 상위 문맥으로 처리하고 있었습니다. 이제 `Chapter/Part/파트`는 상위 문맥으로 유지하고, `N장/N부`는 그 아래에 별도 번호 화가 2개 이상 이어질 때만 상위 문맥으로 봅니다. `1장 / 2장 / 3장`만 나열된 목차는 각 장을 일반 회차로 유지합니다.
- **기존에 작성돼 있었지만 호출되지 않던 `N. 제목` 안전 폴백 연결.** 일반 감지로 화가 거의 잡히지 않을 때 `1. 제목`, `2. 제목` 형식을 위한 전용 스캐너가 실제 자동 감지 경로에서 실행되도록 연결했습니다.
- **버전 표시 통일.** 화면은 v7.9.47인데 내부 생성 리포트 상수 `APP_VERSION`이 v7.9.22로 남아 있던 값을 v7.9.48로 맞췄습니다.

### v7.9.48 회귀 검사

- 전체 HTML의 모든 JavaScript `<script>` 블록을 분리해 **Node.js 문법 검사 통과**.
- 함수 단위 회귀 테스트 통과:
  - 헤더 없는 `1. / 2. / 3.` 앞쪽 목차가 뒤의 실제 `1. / 2. / 3.` 본문보다 먼저 있을 때 앞 목록 전체 제거.
  - 실제 본문에서 번호 체계가 훨씬 뒤에 재시작하는 경우는 삭제하지 않음.
  - `1장 / 2장 / 3장` → 상위 문맥으로 오인하지 않고 세 회차로 유지.
  - `Chapter 1 → 1. / 2.`, `Chapter 2 → 1. / 2.` → Chapter별 문맥 분리 유지.
  - 다권 EPUB 권 내부 후보가 `부가 페이지 → 1화 → 2화` 순서여도 붙여넣은 `1화 → 2화`가 실제 `1화 → 2화`에 연결되고 부가 후보가 목차에 자동 삽입되지 않음.
- 정적 경로 검사: **자동 TXT / 권 있는 붙여넣기 TXT / 권 없는 붙여넣기 TXT** 세 경로가 동일한 헤더 없는 목차 제거 함수를 호출하는지 확인.

> v7.9.47 README의 “붙여넣은 목차 경로에도 적용” 설명은 범위가 과하게 적혀 있었습니다. 실제 코드에서는 권 헤더가 있는 붙여넣기 경로만 수정되어 있었고, 권 없는 평탄 목차 경로가 누락돼 있었습니다. v7.9.48에서 이 차이를 제거했습니다.

## v7.9.47 변경 (이번 판)

- **v7.9.46을 '붙여넣은 목차' 경로에도 적용 (예: '천생연분을 만들어 드립니다').** v7.9.46은 자동 감지에만 반영돼서, 목차를 직접 붙여넣어 매칭할 때는 여전히 앞 화들이 빈 본문이 되고 마지막 화가 전체 본문을 삼켰습니다. 이제 붙여넣기 매칭에서도 **'목차' 헤더 없이 번호만 나열된 앞 덩어리(본문이 비고 같은 제목이 뒤에서 실제 본문과 함께 다시 나오는 경우)를 목차 목록으로 보고 제거**합니다. `외전 1.`/`외전 2.`, `#1`/`#2`처럼 번호·외전·해시가 섞인 목차도 각 화에 본문이 정확히 배정됩니다.



## v7.9.46 변경

- **'목차' 헤더 없이 번호 목록(1. 2. 3.)만 있는 파일에서 앞 화들의 본문이 비던 문제 수정 (예: '천생연분을 만들어 드립니다').** 이 파일은 `목차`/`차례` 같은 헤더 없이 `✲` 장식 뒤에 `1. 2. 3.` 목록이 있고, 그 뒤 본문에도 `1. 2. 3.`이 나와서 목록이 본문 화로 중복 인식돼 앞 3개가 '본문 없음'이 됐습니다. 이제 **앞쪽 마커의 본문이 (거의) 비어 있고 같은 번호가 뒤에서 실제 본문과 함께 다시 나오면, 그 앞 덩어리를 목차 목록으로 보고 제거**합니다. (숫자가 계속 증가하기만 하는 일반 파일은 번호가 반복되지 않으므로 영향 없습니다.)



## v7.9.45 변경

- **숫자 화 없이 '본편 + 외전'만 있는 TXT를 자동으로 못 잡던 문제 보완 (예: '라커룸의 비밀구멍', '호랑이와 고양이…').** 이런 파일은 화 번호도 내부 목차도 없고, 외전이 `라커룸의 비밀구멍 외전`이나 `…방 탈출(외전-…)`처럼 작품 제목과 붙어 있어 기존 감지에 걸리지 않았습니다. 이제 다른 방식으로 화가 거의 안 잡힐 때, **앞뒤가 빈 줄인 짧은 '외전/번외/후일담/특별편' 구분선**을 외전 시작으로 인식하고, 그 앞 전체를 본편으로 잡습니다. 본편 제목은 파일 상단의 작품 제목 줄에서 가져오며, `〈… 마침〉` 같은 종료 표시는 제외합니다.



## v7.9.44 변경 — 전체 종합 점검

- **Calibre 변환 EPUB이 6단계 '생성'에서 실패하던 문제 수정 (예: '스펠바운드').** v7.9.43에서 제목('알 수 없음')은 고쳤지만, 생성 단계에서 본문 XHTML이 유효한 XML이 아니라 내부 검증이 막혔습니다. Calibre 본문은 `&nbsp;`처럼 정의되지 않은 엔티티, `<body>` 여는 태그 누락, 잘못된 태그 중첩 등이 흔합니다. 이제 각 XHTML을 최종 EPUB에 넣기 전에 **유효한 XML로 자동 복구**합니다: (1) 알려진 HTML 엔티티는 숫자 참조로 변환하고 알 수 없는 `&`는 이스케이프, (2) 엄격 파싱이 실패하면 관대한 HTML 파서로 읽어 유효한 XHTML로 다시 직렬화. 본문 내용은 그대로 보존됩니다.
- 권 경계 파트 병합 검사도 파싱 불가 페이지에서 멈추지 않고 건너뛰도록 했습니다.
- **종합 회귀 확인:** 할로윈·불야성·도해늘·파도젤리·7분천국·내편·테일러버드(TXT), 나이트크럽·페어·소소·새벽·스펠바운드(EPUB), 화 번호 범위까지 전부 정상 동작을 재확인했습니다.



## v7.9.43 변경

- **Calibre로 변환된 EPUB에서 화 제목이 '알 수 없음'으로 뜨던 문제 수정 (예: '스펠바운드').** Calibre 변환본은 (1) 목차(NCX)가 사실상 비어 있고, (2) 모든 파일의 `<title>`을 '알 수 없음'으로 채우며, (3) 화 번호를 `<div class="number-item">15.</div>`처럼 담고, (4) 본문 XHTML에 XML 오류가 있어 파싱이 실패하는 경우가 많습니다. 이 때문에 제목이 '알 수 없음'이나 파일명(`index_split_000.html`)으로 떨어졌습니다.
  - `<title>`이 '알 수 없음/Unknown/제목 없음' 같은 placeholder면 무시합니다.
  - 헤딩이 없으면 `number-item`의 화 번호를 제목으로 씁니다.
  - **XML 파싱이 실패해도 정규식으로 제목(헤딩·번호·본문 첫 줄)을 뽑아** 파일명으로 떨어지지 않게 했습니다.



## v7.9.42 변경

- **EPUB 합본 생성이 `sgc-nav.css → href 누락`으로 실패하던 문제 수정 (예: '새벽을 여는 범' 합본, 4권 원본).** 원인은 원본 EPUB(Sigil 계열) 일부가 스타일시트를 `../Styles/sgc-nav.css`가 아니라 **`sgc-nav.css`처럼 디렉터리가 빠진 잘못된 경로**로 링크하고 있었기 때문입니다. 관대한 뷰어는 넘어가지만, 합본 시 각 권을 하위 폴더로 옮기면 이 깨진 링크가 실제로 없는 파일을 가리켜 내부 검증이 막았습니다.
  - 스타일시트 링크를 재작성할 때, 경로가 어긋나면 **파일명(basename)으로도 실제 CSS를 찾아** 올바른 경로로 연결합니다.
  - 링크 속성 순서(`href`가 `rel`보다 앞에 오는 경우 등)와 무관하게 처리합니다.
  - 어떤 실제 CSS에도 연결되지 않는 '깨진 스타일시트 링크'는 안전하게 제거해 생성이 막히지 않게 합니다.



## v7.9.41 변경

- **`1권: 1화~30화` 같은 화 번호 범위가 'Chapter NN'·'#N장' 형식 파일에서 안 되던 문제 수정.** 범위 기능이 화 번호를 읽을 때 `1화`·`1.`·`제1화`·`01`만 인식하고 **`Chapter 01`, `Chapter 05_return`, `#1장`은 번호로 못 읽어서**, 영문 챕터/해시 형식 파일에 범위를 쓰면 한 화도 못 찾았습니다. 이제 이 형식들도 화 번호로 인식합니다. (범위 파싱 자체는 공백 유무와 무관하게 정상이었고, 매칭 단계의 번호 인식이 문제였습니다.)



## v7.9.40 변경

- **권 경계로 갈리는 파트 화(예: '내 편' `Chapter 05_return (1)`/`(2)`)가 배정 안 되던 문제 수정.** 본문에는 3권에 `Chapter 05_return`(파트 번호 없이) 한 번만 있고, `(2)`에 해당하는 내용은 4권 앞부분에 **제목 없이 이어지는** 구조였습니다.
  - `(1)`,`(2)` 같은 괄호 파트를 파트 표기로 인식하도록 했습니다.
  - 본문에 파트 라벨이 없으면 기본 제목으로 매칭해 `(1)`을 본문의 해당 화에 연결합니다(본문에 `(1)`/`(2)`가 실제로 있는 파일은 종전대로 정확히 구분).
  - `(2)` 이상 이어지는 파트는 해당 권 **시작부(제목 없이 이어지는 내용)** 를 찾아 배정합니다.
- 이전 판에서 편집이 중간에 끊겨 목차 붙여넣기 매칭이 실행 중 오류로 동작하지 않던 문제도 함께 해결했습니다.



## v7.9.39 변경

- **목차에서 화 번호를 다시 매긴 파일에서 1권이 통째로 미배정되던 문제 수정 (예: '7분의 천국').** 목차는 `1~8`로 번호를 매겼는데 본문은 원래 번호(`1, 8, 9, 10 …`)를 유지한 경우, 제목이 같아도(`2. Untouchable` ↔ 본문 `8. Untouchable`) 번호가 달라 매칭이 막혔습니다(원래 날짜·'Momentum 1장/2장' 구분용 규칙이 과하게 적용됨). 이제 **`N. 제목` 형식에서 번호 뒤 '제목'이 같으면 앞 번호가 달라도 같은 화**로 인식합니다. 날짜(`1992년 6월 14일` vs `15일`), `Momentum 1장`/`2장`, `3.(1)`/`3.(2)`처럼 번호 자체가 정체성인 경우는 종전대로 구분합니다.



## v7.9.38 변경

## 지원하는 목차 형식

### 권(볼륨) 구분
- `[1권]` 대괄호형
- `<2권>` 꺾쇠형 (그리고 `【3권】`·`《외전 권》` 등 전각 괄호)
- `제4권`, `1권`
- `5권 (외전)`, `6권 (외전2)` → **권으로 인식**
- (별도 외전권은 `외전 권` 또는 `[권] 외전`)

### 화(챕터)
- 번호만: `1`, `2`, `01`
- 한글/임의 제목: `어느날`, `그날 밤`
- `1화`, `제3화`, `1장`, `제2장` 등
- **날짜형 제목**: `1992년 6월 14일 일요일`처럼 날짜가 곧 화 제목인 일기/연재 형식
  - 서로 다른 날짜(요일까지 달라도)를 유사도로 잘못 합치지 않습니다
  - **에필로그의 중복 날짜**(예: 1권 첫 화와 같은 `1992년 6월 14일`)도 각각 제 위치에 정확히 배정

### EPUB 내부 화 자동 감지
- heading(h1~h6)이 없고 `<p><b>01.</b></p>`처럼 **굵은 숫자 문단**으로만 화가 구분된 EPUB(Calibre 변환본 등)도 자동으로 화를 나눕니다.
- 한 권이 여러 파일(index_split_000/001/002 …)로 나뉘어 있어도, 그 안의 굵은 숫자 화를 모두 찾아 쪼갭니다.
- **오탐 방지**: 본문 속에 우연히 들어간 숫자(예: 삐삐 화면 `0 1 2 4.`, `6.25` 같은 표기)는 화로 잡지 않습니다. `<b>`/`<strong>`로 강조됐거나 heading 태그인 순수 번호가 2개 이상일 때만 화로 인식합니다.
- 목차 없이 자동으로 잡히지만, 원하면 `1권` 아래 `1 ~ 13`처럼 범위를 붙여넣어 명시할 수도 있습니다.

### 상위 구분(문맥) — 그 아래 화 번호가 재시작돼도 OK
- `chapter 1`, `Chapter 1` (대소문자 무관)
- `Chapter One`, `Chapter Two` … (영어 숫자 단어)
- `[chapter 1]` (괄호로 감싼 형태)
- `part 1`, `파트 1`
- `제1장 / 1장`, `제1부 / 1부`
- **각 구분 아래에서 `1·2·3`처럼 번호가 다시 시작해도** 문맥별로 서로 다른 본문에 정확히 배정
- **구분 제목 자체에 본문이 있어도, 없어도, 섞여 있어도** 모두 처리
  - `장 / 부`는 그 아래 번호가 재시작되면 상위 문맥으로, 아니면 그냥 회차로 **자동 판단**

> 오탐 방지: `1장면 전환`·`1부분만`·`장난감`·`부산 여행`처럼 우연히 장/부가 들어간 일반 제목은 문맥으로 잡지 않습니다.

## 무엇이 문제였고 어떻게 고쳤나 (요약)

1. **꺾쇠·전각 괄호 권(`<2권>` 등)을 못 잡던 문제** — 권 헤더/마커 판정을 대괄호·꺾쇠·전각 괄호 모두 인식하도록 확장하고 괄호를 벗겨 정규화.
2. **chapter 번호 재시작에서 뒤 화가 비던 문제(가장 심각)** — 본문 시작을 "제목 반복 + **바로 다음 실제 줄이 산문**"일 때로 판정(`nextNonBlankIsProse`). 구분선(`* * *`)·워터마크(`@…`)는 건너뜀. 내부 목차 범위 탐지와 자동 추출 양쪽에 적용.
3. **순수 번호(`1`, `01`) 헤딩이 매칭 안 되던 문제** — 숫자만으로 된 한 줄을 헤딩 번호로 인정.
4. **본문 없는 chapter가 생성을 막던 문제** — chapter/part 같은 구조 제목은 미배정이어도 차단 대상에서 제외.
5. **chapter 표기 확장** — `Chapter One`(영어 숫자단어)·`[chapter 1]`(괄호형)·`제1장/1장`·`제1부/1부`를 문맥으로 인식. 영어 숫자단어는 번호로 환산해 `Chapter One`/`Chapter Two` 라벨이 뒤섞이지 않게 처리.
6. **날짜형 목차가 서로 섞이던 문제** — `1992년 6월 14일`처럼 날짜가 제목이면, 기존 매칭이 맨 앞 숫자(연도 1992)만 보고 유사도로 이웃 날짜까지 끌어와 권 배정이 뒤엉켰습니다. → **양쪽 다 숫자를 포함하고 숫자열(선행 0 무시)이 다르면 유사도와 무관하게 다른 화**로 판정. 요일이 달라 어간 비교를 우회하는 경우까지 차단. 중복 날짜(에필로그 등)도 권 구간·순서로 정확히 배정.
7. **EPUB '굵은 숫자' 화 자동 감지** — heading 없이 `<p><b>01.</b></p>`로만 화가 구분된 EPUB도 자동 분할. 권이 여러 파일로 나뉘어 있어도 그 안의 번호 화를 모두 찾음(순수 번호 화 2개 이상 + 굵게/heading 조건). 본문 속 숫자(삐삐 화면 등)는 오탐 제외.
8. **(이전 판 유지) "차례" 내부 목차 인식** — 헤더가 `목차`·`차례`·`목 차`·`contents`여도 인식, 워터마크·산문 오인 방지, 1화짜리 권 정상 분리.

> 목차 파서/매칭 엔진의 핵심 알고리즘은 유지했습니다. **인식 범위(헤더·항목·권 괄호·chapter 표기)와 헤딩-번호 인식, 본문 시작 판정**만 정교화했습니다.

## 검증 (모두 실제 코드 실행으로 확인)

- **`_할로윈_핏탕물_1-9권.zip`**: 9권 전부 정상 분리, **23화(01~22 + 외전), 빈 본문 0** — 회귀 통과
- `[1권]` + 번호/한글제목, `<1권>`/`<2권>` 꺾쇠 권, `5권 (외전)`/`6권 (외전2)` — 정확
- **chapter 재시작**(각 chapter 아래 1·2·3화): 문맥별로 서로 다른 올바른 본문에 배정, 미배정 0
- **새 4형식 종합 테스트**

  - `제1장 / 제2장` 재시작 — 정확, 미배정 0
  - `1장 / 2장 / 3장`(재시작 없음 = 회차) — 각 장이 회차로 정확 매칭
  - `제1부 / 제2부` 재시작 — 정확, 미배정 0
- **본문 없는 구조 제목**(chapter 1 등): 미배정으로 남아도 생성 차단되지 않음

- **날짜형 목차(일기 형식)**: 권별 날짜 배정 정확, 서로 다른 날짜 안 섞임, 에필로그 중복 날짜도 제자리 배정, 미배정 0
- **실제 EPUB 7권(`_쇼타_나이트크럽_연정.zip`)**: heading 없이 굵은 숫자로만 구분된 형식 → **7권 전체 77화(1~77 연속) 자동 분할 정확**, 4권 본문 속 숫자(삐삐 화면) 오탐 0

## 사용 팁

- **합본(한 TXT에 여러 권)**: 파일 안에 `<2권>`·`[3권]`·`제4권`·`5권 (외전)` 같은 줄이 있으면 자동으로 권을 나눕니다.
- **붙여넣는 목차**: 권 헤더는 `[1권]`·`<2권>`·`5권 (외전)`처럼, 하위 화는 그 아래 `1`/`어느날`/`1화`처럼. 상위 구분은 `chapter 1`·`제1장`·`제1부` 등으로 두고 번호를 재시작해도 됩니다.
- **chapter 재시작이 있는 파일**은 목차를 붙여넣는 방식이 가장 정확합니다(문맥 구분이 확실해짐).
- `장`/`부`가 실제로는 회차인지 상위 구분인지는 그 아래 번호 재시작 여부로 자동 판단하지만, 애매하면 목차를 붙여넣어 명확히 해주세요.
- 특이 형식으로 목차가 안 잡히는 파일이 있으면 그 파일의 **목차 헤더 표기와 제목 몇 줄**을 알려주시면 바로 반영하겠습니다.

## 자주 하는 실수 (중요)

- **목차와 본문의 형식은 같아야 합니다.** EPUB 본문의 화 제목이 숫자(`01. 02.`)인데 목차 칸에 날짜(`1992년 6월 14일`)를 붙여넣으면 서로 매칭되지 않아 "미배정·본문 없음"이 대량 발생합니다.
- **홈페이지(연재 사이트) 목차**를 그대로 붙여넣을 때는, 그 목차의 화 개수·순서가 EPUB 실제 화와 정확히 같은지 먼저 확인하세요. 사이트에서 회차를 합치거나 빠뜨린 경우 개수가 어긋나 뒤로 갈수록 다 밀립니다.
- 숫자로만 구분된 EPUB은 **목차 칸을 비우고 자동**으로 두는 것이 가장 확실합니다. 굳이 넣으려면 `1권` 아래 `1 ~ 13`처럼 숫자/범위로 넣으세요(날짜 X).
