# EPUB Studio Mobile v7.9.23

`_할로윈_핏탕물_1-9권.zip`(TXT 9개 합본)에서 발생한 **"본문 비어 있음"** 문제를 원인부터 파악해 수정했습니다.

---

## 무엇이 문제였나 (진단)

이 작품의 각 권 TXT는 앞부분에 내부 목차를 **"차례"** 라는 제목으로 두고, 그 아래에 `01. …`, `02. …` 처럼 화 제목을 나열한 뒤, 실제 본문에서 같은 제목이 다시 나옵니다.

```
차례                     ← 내부 목차 헤더 (이 프로그램이 못 알아봄)
01. 내리치는 벼락에       ← 목차 항목
02. 켜켜이 쌓인 물에
03. 내리꽂힌 창살에 (1)
TNT@공금 갠소            ← 워터마크
(서두 산문 몇 줄)
01. 내리치는 벼락에       ← 여기서부터 진짜 본문
…
```

기존 코드의 내부 목차 감지기(`extractEmbeddedToc`, `detectInternalTocRange`)는 헤더를 **"목차"·"contents"** 만 인식했고 **"차례"는 인식하지 못했습니다.** 그 결과:

1. **본문 비어 있음** — 내부 목차가 걸러지지 않아, 목차의 `01./02./03.` 줄이 화 시작점으로 잡혔습니다. 바로 다음 목차 줄까지가 "본문"이 되니 사이 내용이 없어 빈 화가 생겼습니다.
2. **워터마크·서두 산문이 가짜 화로** 잡힐 위험 — 목차와 본문 사이의 `TNT@공금 갠소` 같은 워터마크, 서두 산문이 화 제목으로 오인될 수 있었습니다.
3. **1화짜리 권 누락** — 3권처럼 화가 하나(`07. 쌓인 바람에`)뿐인 권은, 감지기가 "목차 항목 2개 이상"을 요구해서 아예 분리되지 않고 통째로 한 덩어리가 됐습니다.

## 수정 내용

### 1. "차례"를 내부 목차 헤더로 인식
- 내부 목차 헤더 판정을 `isTocHeaderLine()` 한 곳으로 통일하고 **목차·차례·목 차·차 례·contents·table of contents** 를 모두 인식합니다.
- 적용 지점: 내부 목차 추출(`extractEmbeddedToc`), 목차 구간 스킵(`detectInternalTocRange`), 본문 위치 점수(`candidateBodyScore`), EPUB 부가 페이지 판정(`isLikelyNonBody`).

### 2. 목차 항목만 골라 워터마크·산문 오인 방지
- `looksLikeTocEntry()` 를 추가해, 목차 영역에서 **진짜 목차 항목처럼 보이는 줄만** 수집합니다.
- `@`가 든 워터마크 줄, 문장부호로 끝나는 긴 산문 줄은 항목에서 제외합니다.
- 목차에 나열된 제목이 본문에서 **다시 등장하는 위치**를 화 시작점으로 삼아, 목차 자체가 아니라 실제 본문을 잡습니다.

### 3. 1화짜리 권도 정상 분리
- 내부 목차 감지의 최소 조건을 "항목 2개 이상"에서 **"1개 이상"** 으로 낮춰, 3권처럼 화가 하나뿐인 권도 올바르게 분리됩니다. (실제 본문에서 제목이 반복될 때만 인정하므로 오탐 위험은 없습니다.)

> 이번 판에서도 목차 파서/매칭 엔진의 핵심 알고리즘은 바꾸지 않았습니다. 내부 목차 **헤더 인식 범위**와 **항목 선별**, **단일 화 처리**만 보강했습니다.

## 사용 방법

1. 프로그램(`index.html`)을 열고 **1번 모드**로 `_할로윈_핏탕물_1-9권.zip` 을 넣고 **분석**합니다.
   - 상태창에 `내부 목차로 찾은 화: 23개` 로 표시되면 정상입니다.
2. 목차 붙여넣기 칸은 비워둔 채, 필요하면 **원본 목차로 자동 구성**으로 권/화 구성을 확인합니다.
3. **4-1 목차 확인·수정** 에서 각 화의 "본문 있음"을 확인한 뒤 생성합니다.
   - 서두의 아주 짧은 도입 산문(차례와 1화 제목 사이의 몇 줄)은 워터마크와 섞여 있어 화 본문에 포함하지 않습니다. 필요하면 1화 미리보기에서 확인 후 직접 추가하세요.
